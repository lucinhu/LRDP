# 剪贴板与文件传输

连接前，在“连接偏好”中开启“共享文字剪贴板”。服务端也需要允许剪贴板重定向。

本机复制文字后，在远程电脑中点选目标输入框，打开悬浮工具栏的“更多”，选择
“粘贴本机文字”。此操作读取本机剪贴板，等待远端确认文字格式后发送 Ctrl+V；
每次最多 16384 个 UTF-16 单元。提示“已发送”表示协议流程完成，目标应用仍需允许粘贴。
没有文字或系统拒绝读取时会显示提示。

桌面端在远程画面获得焦点时，也会每秒检查一次本机文字剪贴板。等待同步后，
可以在远程画面按 Ctrl+V。“同步剪贴板”只同步文字，不会自动按下远端 Ctrl+V。
手机端读取本机剪贴板需要明确操作，使用“粘贴本机文字”即可。

RDP 的 [CLIPRDR 协议](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-rdpeclip/fb9b7e0b-6db4-41c2-b83c-f889c1ee7688)
具备图片和文件格式协商、文件流传输能力；LRDP 当前只实现 Unicode 文字剪贴板。
截图图片及从文件管理器复制的文件，暂不能通过 Ctrl+V 直接跨设备粘贴。

传输图片文件或其他文件：

1. 在“连接偏好”中开启“文件传输”，重新连接使其生效。
2. 打开“更多 → 文件中转站 → 放入本地文件”，选择需要传输的文件。
3. 在远程 Windows 的文件资源管理器地址栏输入 `\\tsclient\LRDP`，将文件复制到远端目录。
4. 反向传输时，把远端文件复制到该目录，再从中转站“另存到本地”或“保存或分享”。

服务端需实现并允许磁盘重定向；这一流程使用 RDPDR 目录共享。图片若只有剪贴板内容，
需先在本机保存成图片文件，再放入中转站。选择了指定共享目录时，远端可读写其中的文件。

## 远端是 Linux 时

Linux 版 LRDP 已实现 RDPDR 客户端；远端 Linux 的支持取决于运行的 RDP 服务端，
不能把 Windows 的 `\\tsclient\LRDP` 路径直接用在 Linux 文件管理器里。

| Linux 服务端 | 上游能力与 LRDP 当前范围 |
| --- | --- |
| [xrdp](https://github.com/neutrinolabs/xrdp) | 支持磁盘重定向和文字、图片、文件剪贴板；LRDP 当前可提供共享目录，文件剪贴板未接入。远端挂载位置由 xrdp 的 `FuseMountName` 配置决定。 |
| [GNOME Remote Desktop](https://github.com/GNOME/gnome-remote-desktop/blob/main/src/grd-clipboard-rdp.c) | 上游实现图片与文件剪贴板；LRDP 当前尚未实现这些剪贴板格式，不能把它当成已支持目录共享。 |
| [KDE KRDP](https://github.com/KDE/krdp/blob/a08961e64dd85d80681acdb3d6d3fb9ef1d6818c/src/Clipboard.cpp) | 核对的上游版本仅处理文字，且显式关闭文件剪贴板；文件传输不能仅靠客户端开启选项实现。 |

以上为 2026-10-20 的上游文档/源码核对，不代表当前 LRDP 与每个服务端都已完成互通实测。
本轮文件协议证据仍来自独立回环服务；用户远端未重新连接。
