LRDP **0.6.0 开发预览**（`v0.6.0-preview.1`，Android versionCode **9**）。

本次提供 Linux x86_64 AppImage、Android ARM64 正式签名 APK、完整源码、FFmpeg / nv-codec-headers 重建资料、构建日志和 SHA-256 校验文件。安装包从本标签提交构建；原生 ABI 保持 v5，FreeRDP 3.32.2 子模块源码未修改。

## 本次变化

- **Android 实验性 MediaCodec H.264 路径**：Android 10 / API29 及以上按系统能力筛选明确标记为硬件、非软件且支持 YUV420 Image 的组件。只有当前 AU 真正输出有效图像后，才在会话信息中报告“硬件（MediaCodec）”。API24–28 保守使用 CPU。
- **失败回退 CPU**：设备不可用、同步输出超时、格式或图像布局不支持时，按顺序重放必要的 SPS/PPS 与 IDR 起参考帧，再继续软件解码。历史有内存与包数上限，不同时进行两份解码。队列与输出等待共享 200 ms 期限，厂商同步 configure/stop 调用不具备可强制中断的硬期限。
- **实际后端与诊断**：会话信息和匿名诊断增加 MediaCodec 后端；保留 Linux 的 CPU / VA-API / CUDA 显示。组件被枚举或创建成功不视为硬解成功。
- **图像与生命周期处理**：按 Image 平面的裁剪、行步长和像素步长复制到自有 I420 缓冲，复用可写缓冲并释放 Image / codec 资源；保留现有 Android 原生纹理和静态画面降载。

## 验证与重要限制

**本版本的 Android 硬解路径属于实验实现，尚未验证到真实 MediaCodec Image/JNI 成功出帧，也未完成 ARM64 手机真机验收，不能承诺 CPU 或功耗下降。**

本地已通过：

- 原生 CTest **8/8**；Flutter **289 passed / 11 skipped**、分析无问题；Java host 核心 304 项、受保护测试入口 19 项、渲染与插件 143 项。
- NDK27 / API24 的 x86_64、ARM64 Release 原生构建、31 项 C ABI + 8 项 JNI 导出、16 KiB 对齐及 Release 禁用测试注入入口检查。
- API26 / API36 x86_64 模拟器私有 TLS / RDPGFX AVC420 的 CPU 路径：真实 9 AU IDR/P、三色完整像素、静止帧、输入和停止清理。API36 的虚拟 Goldfish 组件尝试后超时，正确回退 CPU；系统硬件标记不证明物理加速。
- Linux 实际 CUDA AVC420 和输入 / 停止回归。

**未通过的正例也保留记录**：强制软件 C2 的 MediaCodec 桥测试在首 AU 入队后同步等待超时；OMX 名称映射同一个 C2 实现，去 AUD 实验也未取得输出。未扩大期限、补喂其他 AU 或放宽后端 / 像素标准使其通过。这些失败不作为硬解通过，详见源码内 `docs/VERIFICATION.md`。

发布流水线重新执行分析、Flutter / Python / Java host / 原生测试、APK 结构 / 签名 / 主入口 / 16 KiB 校验以及 AppImage payload / glibc 校验。实际发布构建日志随 `lrdp-0.6.0-verification.zip` 附带，本地模拟器与流水线验收范围分别记录。

仍待验收：成功的 Android MediaCodec Image/JNI 路径、ARM64 手机及不同厂商 codec、真实 AVC444 / AVC444v2、CPU 降幅 / 耗电 / 长时间稳定性、VA-API 成功路径，以及本轮 AppImage 的交互式桌面验收。Windows / Apple 硬解未实现，本次不提供这些平台安装包。GPU 图像仍需下载 / 拷贝、GDI 合成和纹理上传，不是端到端零拷贝。

## 安装与查看后端

Android ARM64 APK 使用沿用的正式发布密钥，可覆盖升级之前的正式签名版本。先前本地开发签名测试包与正式包签名不同，不能直接覆盖；请先通过应用导出不含密码的配置并妥善保留凭据，再决定是否卸载测试包（卸载会清除应用数据）。

使用“自动”或“省流量”画质重新连接，在“更多 → 会话信息 → 编码”查看最近实际使用的后端；“清晰文字”不使用 H.264。若显示 CPU，不应据此假定硬件路径成功。

```sh
chmod +x lrdp-0.6.0-linux-x64.AppImage
./lrdp-0.6.0-linux-x64.AppImage
sha256sum -c SHA256SUMS
```

Linux 需要 glibc ≥ 2.35 和可用的 OpenGL / EGL；无 FUSE 时可用 `APPIMAGE_EXTRACT_AND_RUN=1`。Linux 硬解仍需要宿主机厂商驱动与设备访问权限，不支持时自动回退 CPU。完整源码与固定版本依赖归档、构建信息、摘要随本次 Release 发布。
